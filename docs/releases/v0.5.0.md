# StashDrop 0.5.0

Circle to Search now requests Google's interface from every entry point. StashDrop's internal screenshot, lasso, recognition and results workflow has been removed.

## Changed

- Home/Settings buttons, bubble hold, notification action, enabled marker gestures and the optional assistant entry all use the same Google-only router. Missing Google, inactive voice service and rejected requests show setup guidance.
- Connected Shizuku requests the active Google voice service through the contextual-session API under shell identity; the app-level request remains best effort. Google decides whether Circle to Search, Gemini or its assistant appears. An accepted request is not proof of the displayed UI, and unsupported devices cannot be unlocked by this app.
- Gesture controls now display markers in 88 × 40 dp touch areas above system navigation. Center supports upward swipe/flick, long-press and double-tap; side markers support diagonal up-and-inward corner swipes.
- Unchanged settings preserve pending taps. Android touch slop/timing, distance checks, cancellation, multi-touch and detach handling prevent stale or repeated triggers. Invisible gesture navigation no longer hides the markers. They hide for keyboard, landscape, lock and the search hand-off.
- Removed the Google/built-in toggle, screenshot onboarding, screenshot accessibility and MediaProjection services, shell capture API, ML Kit models and Lens cutout actions. Existing saved shelf items and collections remain.
- Shizuku's basic setup grants overlay/notification access without changing assistant selection. The explicit advanced StashDrop assistant action also attempts to connect Google's voice service.
- Updated the feature/platform/architecture guides, seven production UI renders, roadmap and Windows testing instructions.

## Install and test

Install `StashDrop-v0.5.0.apk` as an update. This release uses version code **8**, the same package/Room schema, and the **original production certificate**. No signing-key replacement or uninstall is needed for compatible official installs.

Choose Google as digital assistant and enable Circle to Search in phone navigation settings if offered. Connect authorized Shizuku if the request is blocked. Show the floating bubble, then enable corner swipe, hold and double-tap individually under **Settings → Gestures, clipboard & feel**. Start gestures on the visible markers; these are separate from system navigation.

## Validation and limits

The accompanying `release-verification.json` records executed automated tests, lint, signing continuity and alignment checks. Tests exercise the reflected contextual-session API on API 28/35, active-Google identity checks, Google rejection without internal fallback, persisted old preferences, gesture recognition/cancellation on API 28 and 35, floating-service behavior, dashboard actions and production renders.

No physical phone/tablet or emulator was attached to the cloud. Google/OEM behavior and the user's connected tablet still require device testing. The [Windows ADB guide](https://github.com/ankitchanki/StashDrop/blob/main/docs/WINDOWS_DEVICE_TESTING.md) explains local installation and bounded logging; the cloud cannot reach a laptop's local ADB merely because laptop and tablet share Wi-Fi.
